## Root Cause Analysis

### Crash on IPC quit (tests #1 and #3)

The current IPC quit path chains three layers of deferral:

```text
IPC thread
  -> invoke_from_event_loop(closure)     [queues UserEvent]
     -> Timer::single_shot(Duration::ZERO, closure)  [queues timer]
        -> quit_event_loop()             [queues Exit event]
```

The zero-duration single-shot timer can fire while wgpu is
mid-frame. The resulting teardown sequence (Drop chain for
`WinitWindowAdapter` -> `FemtoVGRenderer` -> `RenderingTeardown`
-> `GPU_RESOURCES.take()`) crashes the Vulkan/DX12 backend with
`STATUS_STACK_BUFFER_OVERRUN` (exit code `0xC0000409`).

**Why the render subcommand doesn't crash:** Its timer calls
`quit_event_loop()` from a `Repeated` timer callback that fires
at regular 200ms intervals during a clean event loop iteration
-- never mid-frame. But the underlying reason both *should* work
is the same: `quit_event_loop()` just queues a `CustomEvent::Exit`
to the winit proxy. The exit is processed at the next clean event
boundary, where `suspend_all_hidden_windows()` runs before
`event_loop.exit()`.

**Fix:** Call `quit_event_loop()` directly from the IPC thread.
The Slint documentation explicitly states: *"This function can be
called from any thread."* This eliminates all three layers of
deferral. The `Exit` event goes through the same winit proxy
channel and is processed identically -- but without the
`UserEvent` handler or timer on the call stack, so there is no
risk of interrupting an active render pass.

### Hidden window blocks invoke_from_event_loop (test #2)

When `--tray-start hidden` is used, `window.show()` is never
called. On Windows, this means no native HWND is created. Winit's
Win32 message pump requires an HWND to dispatch events --
without one, `EventLoopProxy::send_event` posts messages that
are never processed. The `invoke_from_event_loop` closures
(for `show-window`, `hide-window`) queue successfully but never
execute.

The test confirms this: `"ipc listener ready"` appears (logged
by the main thread before the event loop starts), but
`"main window shown (from ipc)"` never appears (the
`invoke_from_event_loop` closure never runs).

**Fix:** Always call `window.show()` in tray mode, then
immediately `window.window().hide()` for hidden start. This
creates the native HWND (enabling the message pump) while
keeping the window invisible. The tray icon still appears
normally.

## Implementation Steps

### Step 1: Simplify IPC quit to direct `quit_event_loop()`

**File**: `src/ipc.rs` (lines 72-84)

Replace the `"quit"` arm in `dispatch_command`:

```rust
// Before (3 layers of deferral):
"quit" => {
    debug!("ipc command: quit");
    slint::invoke_from_event_loop(|| {
        slint::Timer::single_shot(std::time::Duration::ZERO, || {
            slint::quit_event_loop().ok();
        });
    })
    .ok();
}

// After (direct call, thread-safe per docs):
"quit" => {
    debug!("ipc command: quit");
    slint::quit_event_loop().ok();
}
```

This also removes the now-unused `use std::time::Duration`
import (if present).

**Verify**: `cargo build`, `cargo clippy`

### Step 2: Ensure native HWND exists for hidden tray start

**File**: `src/main.rs` (lines 336-344)

Change the tray mode window visibility logic:

```rust
// Before:
if matches!(tray_start, TrayStart::Visible) {
    window.show().expect("Failed to show window");
}
slint::run_event_loop_until_quit()
    .expect("Failed to run event loop");

// After:
window.show().expect("Failed to show window");
if matches!(tray_start, TrayStart::Hidden) {
    window.window().hide().ok();
}
slint::run_event_loop_until_quit()
    .expect("Failed to run event loop");
```

**Verify**: `cargo build`

## Optional Follow-up

The tray "Exit" menu handler in `tray.rs:131` uses
`invoke_from_event_loop(|| quit_event_loop())` -- the same
pattern that crashed (without the timer wrapper). This likely
has the same crash potential but is currently untested by e2e.
Consider simplifying it to `quit_event_loop()` directly for
consistency. Not in scope for this fix since it's untested and
the tray module is separate.
